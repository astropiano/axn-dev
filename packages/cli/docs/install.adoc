== Quick Start

[source,bash]
----
cd axn-dev-cli
pnpm install
pnpm build
./build-link.sh   # builds all packages and links 'axn-dev' into ~/.local/bin

# Configure your environment (interactive)
axn-dev init

# Or auto-scan a workspace directory of git checkouts
axn-dev init --scan ~/repos

# Or bootstrap from a GitLab group (clone + register)
axn-dev setup --group myorg/dev --dir ~/repos
----

After `init`, verify everything works:

[source,bash]
----
axn-dev list      # Should show available scenarios
----

=== Global link

`build-link.sh` symlinks the compiled `packages/cli/dist/main.js` into
`~/.local/bin` (override with `AXN_DEV_BIN_DIR`). A plain symlink is used
instead of `npm link`/`pnpm link -g` because npm cannot resolve the pnpm
`workspace:*` protocol and pnpm 10 dropped `link --global`. Node resolves
the symlink to the real file, so `@axn-dev/*` imports and sibling
`packages/*` plugin discovery keep working against the workspace.

Ensure `~/.local/bin` is on your `PATH` (e.g. in `~/.zshrc`), reload your
shell, and rerun `./build-link.sh` from this repository root. The script
warns if `axn-dev` resolves to a different binary earlier on your `PATH`
(e.g. a stale install shadowing the link).
